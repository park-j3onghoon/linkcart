19. 용어집

약어는 풀네임 병기. Python/Django 대응 있으면 병기.

사용법 — 다른 챕터 읽다 모르는 용어 나오면 여기서 찾아보기. 중요한 용어는 각주 형태로 풀어 설명, 나머지는 표로 요약. 각 용어는 id가 있어 다른 챕터에서 #g-용어로 링크 가능.

핫링크 (Hotlink / Inline Linking)

풀네임 — Hotlinking, Inline Linking, Bandwidth Theft(대역폭 절도).

정의 — 내가 호스팅하지 않은 외부 사이트의 이미지/파일 URL을 내 사이트/앱의 <img src="…">에 그대로 박아서 보여주는 행위. 파일이 내 서버를 거치지 않고, 사용자의 브라우저가 직접 원본 서버에 가서 가져온다.

발단 — 초창기 웹에서는 모두가 자유롭게 img src를 아무 URL에나 꽂아 썼다. 그러다 다음 세 가지 문제가 발생했다.

  • 대역폭 도용 — 유명 사이트 이미지를 본인 블로그에 embed하면, 원본 사이트가 트래픽/CDN 비용을 대신 내게 됨.
  • 보안 / 위변조 — 원본이 어느 순간 이미지를 "광고" 또는 "혐오 이미지"로 바꿔치기하면, 내 사이트 방문자에게 그대로 노출.
  • 사생활 추적 — 이미지 요청으로 원본 서버가 방문자 IP/UA를 수집 가능.

쇼핑몰의 대응 — 쿠팡·11번가·네이버 같은 쇼핑몰은 상품 이미지 CDN에 Referer 기반 핫링크 차단을 건다. Referer 헤더가 자기 도메인이 아니면 403 또는 placeholder 이미지를 준다. 따라서 내 앱에서 https://shop.example.com/img/p.jpg를 그대로 <img>에 꽂으면 깨진 아이콘이 뜬다.

이 프로젝트에서 해결한 방식

  1. BE가 URL을 받아 서버에서 직접 이미지 fetch (Referer 없이 또는 원본 도메인 위장).
  2. 바이트를 받아 자체 스토리지(또는 캐시 프록시)에 저장.
  3. FE에는 내 서버의 URL을 내려줌 → 핫링크 아님.

보안 함정 (SSRF 연결) — 서버가 임의 URL을 fetch하면 SSRF 위험이 생긴다. 그래서 이 프로젝트는 fetch 전에 SafeUrlChecker로 schema/host/IP range/redirect/content-type을 모두 검증한다.

참고 — 단순히 referrerpolicy="no-referrer" 속성만으로는 서버가 "자기 도메인 referer 필요" 정책이면 여전히 차단된다. 서버 측 fetch + 재호스팅이 근본 해결책.

OG parser (Open Graph Parser)

풀네임 — Open Graph Protocol Parser.

Open Graph Protocol — 2010년 Facebook이 제안한 HTML 메타 태그 규약. 웹페이지가 "이 페이지는 어떤 상품/글/영상이다"를 구조화해 알리는 표준. 모든 쇼핑몰·뉴스·블로그가 거의 다 박아둔다. SEO + 소셜 공유 preview를 위해서다.

<meta property="og:title" content="아이패드 Pro 11인치">
<meta property="og:image" content="https://cdn.shop.com/ipad.jpg">
<meta property="og:type" content="product">
<meta property="og:url" content="https://shop.com/p/12345">
<meta property="product:price:amount" content="1299000">
<meta property="product:price:currency" content="KRW">

OG parser란 — HTML을 받아 위 <meta property="og:*"> 태그를 뽑아 이름·이미지·가격 등 구조화된 객체로 변환하는 컴포넌트. 이 프로젝트의 OgParser가 그 역할.

왜 OG를 쓰나 — 쇼핑몰마다 HTML 구조가 다르다. div.price, span.productPrice, p#priceArea… 일일이 CSS 셀렉터를 맞추면 10개 쇼핑몰 붙이려고 10개 파서를 만들어야 한다. OG 메타 태그는 거의 모든 쇼핑몰이 표준적으로 박기 때문에, 하나의 OG parser로 8~90% 커버된다.

이 프로젝트의 Fallback Chain

  • 요청 URL의 host를 보고 먼저 전용 파서 시도 (쿠팡 → CoupangParser, 11번가 → ElevenStParser).
  • 실패 또는 전용 파서가 없으면 OG parser로 폴백.
  • OG 태그도 없으면 마지막에 <title>과 첫 이미지 fallback.

한계

  • og:image가 썸네일만 주고 고화질이 아닌 경우 많음.
  • 가격은 og 표준이 아닌 product:price:amount(Facebook 확장) 또는 JSON-LD Product schema를 같이 봐야 정확.
  • 일부 쇼핑몰은 SPA라 서버 HTML에 OG가 비어있고 JS 실행 후에만 채워진다 → headless 브라우저 없이는 못 긁음.

참고 — 07. 파서 진화에서 Parser interface → OgParser → ParserFactory → CoupangParser 추가까지의 과정을 다룬다.
