02. 환경 설정

Python에서는 venv + pip면 끝. JVM 세계는 JDK라는 별도 개념이 있다.

JDK가 뭔가 — Python에는 없는 개념

Python
# python 자체가 실행기
$ python script.py

# 준비: Python 인터프리터 설치
$ brew install python@3.12
$ python --version
Python 3.12.0
Kotlin/Java
# Kotlin 소스 → 바이트코드 컴파일 → JVM 실행
$ kotlinc script.kt # .class 파일 생성
$ java -cp . Script      # JVM으로 실행

# 준비: JDK (Java Development Kit)
$ brew install --cask temurin@21
$ java --version
openjdk 21.0.6

JDK (Java Development Kit)는 "Java 개발자 도구 모음"이다. 컴파일러(javac/kotlinc), 실행기(java), 표준 라이브러리, 디버거 등이 포함된다. Kotlin도 JVM 위에서 돌아가서 JDK가 필요하다.

JDK 버전 — 왜 Java 21?

버전성격이 프로젝트
8, 11, 17, 21, 25, ...LTS (Long-Term Support)선택 대상
기타 버전6개월 주기 릴리스, 단기 지원프로덕션 비추
이 프로젝트는 Java 21 — 현재 Spring Boot 3.x와 Gradle 8.x가 안정적으로 지원하는 가장 최신 LTS. Java 25는 최신이지만 생태계 호환이 덜 익었음.

JDK 배포판 — Oracle, Temurin, Corretto?

OpenJDK 소스를 여러 회사가 빌드해 배포한다. 대부분 기능 동일하지만 라이선스·지원 차이:

설치 — brew 명령어 해부

$ brew install --cask temurin@21
#              ↑       ↑       ↑
#              │       │       └ 버전 지정
#              │       └ 패키지명 (eclipse-temurin)
#              └ 앱 형식 설치 (GUI/바이너리 배포)

--cask는 brew가 CLI 명령이 아닌 앱/바이너리 설치를 할 때 쓰는 플래그. JDK는 /Library/Java/JavaVirtualMachines/에 설치됨.

JAVA_HOME — "어느 JDK를 쓸지" 지정

여러 JDK가 설치되어 있을 때 사용할 것을 명시:

# ~/.zshrc 또는 ~/.bash_profile에
export JAVA_HOME=$(/usr/libexec/java_home -v 21)
export PATH="$JAVA_HOME/bin:$PATH"

# 확인
$ echo $JAVA_HOME
/Library/Java/JavaVirtualMachines/temurin-21.jdk/Contents/Home
Python에는 왜 없나? python/python3 같은 인터프리터 실행 파일이 PATH에 있으면 된다. JDK는 JAR 실행, 컴파일 명령, 개발 툴 등이 JDK 하위 bin/에 같이 있어 "이 JDK 트리 전체"를 지정해야 한다.

Gradle + npm workspaces 두 빌드 시스템 공존

빌드 시스템 두 개 공존 — Gradle + Turborepo

backend — Gradle
# 루트에서
$ npm run build:backend

# 실제로 호출되는 것
$ cd backend && ./gradlew build

# Gradle이 Kotlin 컴파일 + JAR 생성
# build/libs/backend-*.jar
apps + packages — Turborepo
# 루트에서
$ npm run build

# turbo.json의 tasks 정의대로
# shared → codegen → web, mobile 순

# "^build" = "의존하는 패키지를 먼저 빌드"
왜 하나로 통합하지 않나? Gradle은 JVM 전용이고 Turborepo는 Node.js 전용. 각자의 생태계에 최적. 통합하려면 Bazel 같은 범용 빌드 도구가 필요한데 복잡도 급증. 이 규모에선 "각자의 것을 쓰고 루트 npm 스크립트로 오케스트레이션"이 실용적.

환경변수 관리 — .env.example + .env

# .env.example (git-tracked, 템플릿)
POSTGRES_USER=linkcart
POSTGRES_PASSWORD=change-me-local
LINKCART_GOOGLE_CLIENT_ID=
LINKCART_GOOGLE_CLIENT_SECRET=
LINKCART_JWT_SECRET=change-me-to-random-32-plus-byte-string

# .env (.gitignore, 실제 값)
POSTGRES_PASSWORD=my_actual_local_password
LINKCART_GOOGLE_CLIENT_SECRET=GOCSPX-... (Google Cloud Console에서 발급)
...

# 로드
$ export $(grep -v '^#' .env | xargs)
$ cd backend && ./gradlew bootRun

Django의 settings.py처럼 코드 안에 시크릿을 두지 않는다. application.yml은 ${ENV_VAR}로 참조만 하고, 실제 값은 .env나 클라우드의 시크릿 매니저에서 주입.

Docker Compose — 로컬 Postgres

# docker-compose.yml (루트)
services:
  postgres:
    image: postgres:16
    environment:
      POSTGRES_USER: ${POSTGRES_USER:?must be set}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?must be set}
      POSTGRES_DB: ${POSTGRES_DB:?must be set}
    ports:
      - "5432:5432"

# 실행
$ docker compose up -d postgres
$ docker ps  # 확인

:?must be set는 "env 없으면 에러로 멈춤" (fail-fast). 실수로 기본 비밀번호로 실행되는 사고 방지.

정리 — 처음 환경 구성 체크리스트

  1. brew install --cask temurin@21 — JDK 21
  2. JAVA_HOME + PATH ~/.zshrc에 설정
  3. brew install --cask docker 또는 Rancher Desktop — Postgres용
  4. 프로젝트 clone 후 cp .env.example .env, 값 채우기
  5. docker compose up -d postgres
  6. export $(grep -v '^#' .env | xargs)
  7. cd backend && ./gradlew bootRun
  8. http://localhost:8080/docs 열어 Swagger UI 확인
이 문서가 커버하지 않는 것 — Kotlin 문법은 03에, Gradle 내부는 05에, IDE 디버깅 팁은 별도. 여기는 "설치까지"만.
