01. 프로젝트 개요

linkcart는 무엇이며, 왜 이 기술 스택과 구조로 만들었는가.

한 줄 요약

linkcart는 쇼핑몰 상품 URL을 입력하면 상품명·가격·이미지를 파싱해 한 페이지에 모아주는 서비스다. 웹(Next.js)과 앱(Expo React Native) 두 클라이언트를 가진다. 이 문서에서 다루는 건 그중 Kotlin/Spring Boot 백엔드다.

클라이언트 2종 + BE 1종 + 외부 API 3종

무엇을 하는 서비스인가

  1. 사용자가 쇼핑몰 URL을 입력한다 (예: https://www.coupang.com/vp/products/123).
  2. BE는 URL 도메인을 보고 적절한 파서를 선택한다 (쿠팡 → CoupangParser, 11번가 → ElevenStParser, 그 외 → OgParser 폴백).
  3. 상품명·가격·이미지를 추출해 반환한다.
  4. 로그인한 사용자는 이 결과를 자기 리스트에 저장해두고 나중에 다시 볼 수 있다.

왜 "쇼핑몰 링크 파서"인가

주제 선정 기준:

  • 외부 API 호출이 필연 (쿠팡·11번가) → 티니어의 "글로벌 서비스 외부 데이터 파싱" 요구와 맞음
  • Fallback이 필요 (전용 파서 실패 시 OG 파서) → 티니어의 "24/365 장애 없는 환경" 어필 포인트
  • 캐싱이 의미 있음 (같은 URL 재파싱 피함) → @Cacheable 실전 경험
  • SSRF 공격 가능 (서버가 URL을 fetch하므로) → 보안 토픽 실전
  • 멀티 플랫폼 자연스러움 (웹 + 앱) → 티니어 요구와 일치
  • 데이터 규모 작음 → 혼자 할 수 있는 규모. 회원관리까지 넣어도 MVP 가능.
주제 선정 원칙 — 포트폴리오 프로젝트는 "내가 멋지게 보이고 싶은 기술"이 아니라 "이 회사의 요구와 가장 많이 겹치는 도메인"을 선택해야 한다. linkcart는 날씨 앱과 도메인은 다르지만 백엔드 관점에서 마주하는 문제(외부 API, 캐시, fallback, 멀티 플랫폼, 인증, 보안)가 거의 동일하다.
