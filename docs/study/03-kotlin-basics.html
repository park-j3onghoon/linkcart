03. Kotlin 기초 (Python 개발자 관점)

Python과 나란히 비교하며 핵심 문법 7개만 짚는다. 이 문서의 목표는 "이 프로젝트 코드를 읽을 수 있을 정도".

전제 — 여기서 다루는 건 이 프로젝트에서 반복적으로 쓰는 문법이다. Kotlin 전체가 아니다. 코루틴·delegated property·DSL 같은 고급 주제는 프로젝트에 안 나와서 생략.
이 챕터의 핵심 용어 — val / var · data class · sealed class · when · object · companion object · ?. · ?: · !! · let

왜 Kotlin이 Java를 대체했나 (간단 배경)

Java는 1995년 시작. 2000년대 null 안전성 부재, verbose한 getter/setter, 불변 객체 만들기 번거로움이 큰 불만이었다. JetBrains가 2011년에 Kotlin 공개 → 2017년 Google이 Android 공식 언어로 지정. JVM 위에서 동작해 Java 라이브러리 다 그대로 쓸 수 있으면서 문법이 간결. Spring도 5.0부터 Kotlin을 1급 언어로 지원. 그래서 지금 신규 프로젝트는 Kotlin이 기본 선택.

1. val vs var — 불변 vs 가변

Python
# Python은 언어 수준에서 구분 없음
# 관례: 대문자 = 상수 (강제력 없음)
PI = 3.14
PI = 3.15  # 막지 않음

count = 0
count += 1   # 자연스러움
Kotlin
// val = value, 재할당 불가 (컴파일 에러)
val pi = 3.14
pi = 3.15  // ❌ 컴파일 에러

// var = variable, 재할당 가능
var count = 0
count += 1   // ✅ OK

Kotlin은 기본값이 val이다. var는 꼭 필요할 때만 쓴다. Python의 "상수는 관례"와 반대로, 컴파일러가 막아준다. val이어도 내부가 mutable일 수는 있다 (예: val list = mutableListOf<Int>()는 참조는 못 바꾸지만 list에 값 추가 가능).

2. Null safety — 타입에 ? 가 붙는다

Python
# Optional[X] 또는 X | None (Python 3.10+)
from typing import Optional

def find_user(id: int) -> Optional[User]:
    ...

user = find_user(1)
print(user.name)  # 런타임에 AttributeError 가능
# 타입 체커가 잡아주긴 함 (mypy 등)
Kotlin
// 타입 자체에 ? 붙여 null 가능 표시
fun findUser(id: Long): User? { ... }

val user = findUser(1)
// 컴파일러가 non-null 보장 전까지 .접근 금지
user.name           // ❌ 컴파일 에러
user?.name          // ✅ null이면 null 반환
user?.name ?: "익명"  // null이면 "익명"
user!!.name         // ✅ "절대 null 아님" 단언 (위험)
user?.let { println(it.name) }  // null 아닐 때만 실행
!!의 의미 — "null 아님을 보증한다. null이면 런타임에 NullPointerException 던져도 OK". Kotlin 코드 리뷰에서 !!는 원칙적으로 금지. 쓰고 싶으면 requireNotNull(x)나 ?: error("...")로 이유를 드러내는 게 낫다.

3. data class — 값 객체

Python (dataclass)
from dataclasses import dataclass

@dataclass
class User:
    id: int
    email: str
    name: str | None = None

u1 = User(1, "a@b.c")
u2 = User(1, "a@b.c")
u1 == u2  # True (eq 자동 구현)
Kotlin
data class User(
    val id: Long,
    val email: String,
    val name: String? = null,
)

val u1 = User(1, "a@b.c")
val u2 = User(1, "a@b.c")
u1 == u2  // true (equals 자동)

// copy로 일부만 바꿔 새 객체
val u3 = u1.copy(email = "x@y.z")

data class는 Python @dataclass와 거의 같은 자동화를 해준다: equals, hashCode, toString, copy, componentN. 이 프로젝트에서 도메인 객체는 전부 data class다 (User, RefreshToken, UserProduct, Product, ParseResult.Success 등).

4. when — 강화된 switch

Python (match)
def describe(r: ParseResult) -> str:
    match r:
        case ParseResult.Success(product, _, _):
            return f"OK {product.name}"
        case ParseResult.Partial(fields, _, _):
            return f"부분: {fields}"
        case ParseResult.Failure(reason, _):
            return f"실패: {reason}"
Kotlin
fun describe(r: ParseResult): String = when (r) {
    is ParseResult.Success -> "OK ${r.product.name}"
    is ParseResult.Partial -> "부분: ${r.fields}"
    is ParseResult.Failure -> "실패: ${r.reason}"
}  // exhaustive (모든 분기 체크)

when은 Python match와 비슷하지만 값을 반환하는 표현식으로 자주 쓴다. sealed interface와 결합하면 컴파일러가 "모든 경우 다뤘는지" 검사한다. 새 subtype이 추가되면 분기 빠뜨린 곳이 컴파일 에러로 드러난다.

5. sealed interface — 닫힌 계층

Python (ABC)
from abc import ABC, abstractmethod

class ParseResult(ABC): pass

class Success(ParseResult):
    def __init__(self, product): ...

class Failure(ParseResult):
    def __init__(self, reason): ...

# 문제: 다른 파일에서 누구나 상속 가능
# match 분기 빠뜨려도 런타임 전까지 못 잡음
Kotlin
sealed interface ParseResult {
    data class Success(
        val product: Product, ...
    ) : ParseResult
    data class Partial(...) : ParseResult
    data class Failure(
        val reason: String, ...
    ) : ParseResult
}
// sealed: 같은 모듈 내에서만 상속 가능
// when 분기 누락 시 컴파일 에러

이 프로젝트의 ParseResult는 sealed interface로 Success/Partial/Failure 3개만 가진다. "파싱 결과는 정확히 이 3가지 중 하나"라는 도메인 제약을 타입으로 표현.

6. 확장 함수 — 기존 클래스에 메서드 추가

Python
# 기존 클래스 메서드 추가 어려움
# 보통 유틸 함수로 해결
def to_domain(entity: UserEntity) -> User:
    return User(
        id=entity.id,
        email=entity.email,
        ...
    )

# 호출
user = to_domain(entity)
Kotlin
// UserEntity "자체"에 toDomain 메서드 추가처럼
internal fun UserEntity.toDomain(): User = User(
    id = id,
    email = email,
    ...
)

// 호출 — 메서드처럼
val user = entity.toDomain()

확장 함수는 기존 클래스 변경 없이 메서드처럼 호출하는 문법. 이 프로젝트의 Mapper 파일들(UserMappers.kt, RefreshTokenMappers.kt)이 이 패턴이다. JPA entity ↔ 도메인 객체 변환을 깔끔하게 표현.

7. companion object — 클래스 수준 멤버

Python
class ParserName:
    OG = "og"
    COUPANG = "coupang-api"

    @classmethod
    def from_code(cls, code: str):
        return getattr(cls, code.upper())
Kotlin
class ParseResponse(...) {

    companion object {
        fun from(result: ParseResult): ParseResponse {
            ...
        }
    }
}

// 호출 — Java의 static과 유사하지만 object
val res = ParseResponse.from(parseResult)

Kotlin은 static 키워드가 없다. 대신 companion object에 넣으면 클래스 이름으로 접근 가능. 팩토리 메서드(ParseResponse.from(result)), 상수(OgParser.PARSER_NAME) 등에 쓴다.

실전 예시 — 이 프로젝트의 한 파일

위 문법이 어떻게 어우러지는지 RefreshToken 도메인 엔티티를 보면:

package com.linkcart.domain.entity

import java.time.Instant
import java.util.UUID

data class RefreshToken(                   // 3. data class: equals/hashCode/copy 자동
    val id: UUID? = null,                    // 1.val = immutable, 2.? = nullable
    val userId: Long,
    val tokenHash: String,
    val issuedAt: Instant? = null,
    val expiresAt: Instant,
    val revokedAt: Instant? = null,
    val replacedByTokenId: UUID? = null,
) {
    val isActive: Boolean get() = revokedAt == null            // 계산 프로퍼티
    fun isExpiredAt(now: Instant): Boolean = !now.isBefore(expiresAt)
}

7줄 안에 immutable, nullable, data class, 계산 프로퍼티, 순수 함수가 다 있다. Python의 dataclass와 거의 같지만 null 가능성이 타입에 드러나 있다.

심화 Q&A — 자주 헷갈리는 지점

Q. val에 null을 넣고 싶을 때 Int?와 String? 같은 거지? 어떤 걸 권장?

질문의 전제가 약간 섞여 있다. 두 가지를 구분.

  • "val + nullable"과 "Int? 또는 String? 타입 선택"은 다른 축이다.
  • val은 "재할당 금지". 타입이 Int?든 String?든 상관 없다.
  • 어떤 타입을 쓸지는 표현하려는 값이 숫자인가 문자열인가에 따라 결정. 이건 권장의 문제가 아니라 도메인의 문제.
의도에 맞는 타입 선택
// "나이는 선택 입력" → 숫자 nullable
val age: Int? = null

// "닉네임은 선택 입력" → 문자열 nullable
val displayName: String? = null

// nullable이 아예 없는 게 가장 좋음
val age: Int = 0           // 기본값으로 표현
val tags: List<String> = emptyList()  // 빈 컬렉션 = "없음"
권장 순서
  1. non-nullable + 기본값 (Int = 0, List<T> = emptyList())
  2. sealed로 명시 (sealed interface Result { Present(val v: T); Absent })
  3. nullable (Type?) — 위 둘이 부적절할 때만

nullable이 타입에 박히면 모든 소비자가 null 체크를 해야 한다. 가능하면 안 쓰는 게 나음.

Q. !! 대신 뭘 쓰라는 거야?

❌ 권장 안 함
val user = findUser(id)
return user!!.email           // 이유가 안 드러남
✅ 권장
// 방법 1: requireNotNull — 표준 함수
val user = requireNotNull(findUser(id)) { "user $id not found" }
return user.email

// 방법 2: Elvis + 도메인 예외
val user = findUser(id) ?: throw UserNotFoundException(id)
return user.email

// 방법 3: ?.let — null이면 아무것도 안 함
return findUser(id)?.let { it.email }  // 반환 타입 String?

핵심 차이: !!는 NPE만 남기지만, requireNotNull/명시적 throw는 왜 null이면 안 되는지를 메시지로 남긴다. 에러 로그에서 디버깅 힌트가 된다.

Q. data class의 componentN은 뭐야?

자동 생성되는 component1(), component2(), ... 함수. 필드 순서대로. 이걸로 구조 분해 선언(destructuring)이 가능하다.

data class User(val id: Long, val email: String, val name: String?)

val user = User(1, "a@b.c", "앨리스")

// componentN 자동 호출
val (id, email, name) = user
// = val id = user.component1(); val email = user.component2(); val name = user.component3()

println("$id, $email, $name")  // 1, a@b.c, 앨리스

// Map에서도 유용
for ((key, value) in mapOf("a" to 1)) {
    println("$key=$value")
}

Python의 tuple unpacking (id, email, name = user)와 같은 기능. 순서 의존적이라 필드 순서가 바뀌면 소비자가 깨지니 실무에선 많이 안 쓴다. Map/Pair 정도만 주로 사용.

Q. when은 is를 써도 되고 안 써도 돼? 왜 쓰지?

둘 다 가능하지만 용도가 다르다.

is 없이 — 값 비교
when (status) {
    "active" -> doActive()
    "pending" -> doPending()
    else -> doUnknown()
}

// == 동등 비교
// status의 타입은 String으로 이미 알고 있음
is 있음 — 타입 검사
when (result) {         // result: ParseResult
    is ParseResult.Success -> result.product.name
    is ParseResult.Partial -> result.fields["name"]
    is ParseResult.Failure -> null
}

// is 체크 후 smart cast
// "is Success" 분기 내부에서는 result가 자동으로 Success 타입
// → result.product 접근 가능 (Success의 필드)

is를 쓰는 이유:

  • 값이 아닌 타입 계층(sealed 등)에 따라 분기할 때
  • smart cast: is Success가 true인 분기 안에서는 자동으로 Success 타입으로 좁혀진다. 그래서 result.product처럼 subtype 전용 필드에 바로 접근 가능
  • Python의 match case Success(product): ...와 같은 패턴 매칭

Q. 확장 함수 — 실무에서 쓰는 거 맞아? 안티패턴 아냐?

결론부터: 실무에서 매우 많이 쓰는 Kotlin 관용구. 안티패턴 아니다.

왜 "기존 클래스에 추가"가 아니라 확장 함수인가:

  • 남의 클래스는 수정할 수 없다. UserEntity는 JPA 라이브러리가 정의한 @Entity 규약을 따라야 하고, 여기에 도메인 변환 로직을 넣으면 infrastructure가 domain을 의존하게 됨 (레이어 위반).
  • 책임 분리: UserEntity는 "DB 매핑"만, UserMappers.kt는 "변환"만. SRP.
  • 가시성 제어: internal로 선언하면 같은 모듈 밖에는 안 보임. 클래스에 메서드 추가하면 public이 기본.
  • 테스트에서 확장 함수 덮어쓰기 불가: 의존성 주입과 달리 mock 어려움 → 순수 변환 같은 무상태 기능에만 사용.

실무 관례:

용도확장 함수 적합?
DTO ↔ 도메인 변환 (이 프로젝트의 Mapper)✅ 적합
String/Int 같은 표준 타입에 편의 메서드 ("foo".toKebabCase())✅ 적합
라이브러리 타입 확장 (LocalDateTime.toKoreanTime())✅ 적합
복잡한 상태 변경/외부 I/O❌ 부적합 — 클래스 메서드로
의존성 주입 필요한 로직❌ 부적합 — 클래스 메서드로

이 프로젝트의 UserMappers.kt는 "순수 변환 (도메인 ↔ Entity)"이라 확장 함수가 가장 깨끗한 선택. 실제 회사 코드 (Kotlin 기반 JetBrains, Airbnb, Pinterest 등)에서도 같은 패턴 널리 사용.

Jake Wharton의 Kotlin 스타일 가이드, JetBrains 공식 가이드에서도 "도메인 ↔ 영속성 매핑은 확장 함수로"를 권장. 1회용이 아니라 같은 파일에 모아두고 재사용한다. 그 의미에서 "UserMappers.kt"라는 파일 자체가 "확장 함수 모음" 역할.

Q. companion object는 뭘 위해 쓰는 거야? Python 클래스 변수와 비교해줘

Python에서 클래스에 속성/메서드를 붙이는 4가지 방식부터 정리:

Python — 4가지 범주
class ParseResponse:
    # ① 클래스 변수 (static)
    DEFAULT_CURRENCY = "KRW"

    # ② 인스턴스 변수
    def __init__(self, name, price):
        self.name = name     # 각 인스턴스마다
        self.price = price

    # ③ 인스턴스 메서드
    def display(self):
        return f"{self.name}: {self.price}"

    # ④ 클래스 메서드 / 스태틱 메서드
    @classmethod
    def from_result(cls, result):
        return cls(result.name, result.price)

    @staticmethod
    def is_valid_name(name):
        return len(name) > 0
Kotlin 대응
class ParseResponse(
    val name: String,   // ② 인스턴스 프로퍼티
    val price: Long,
) {
    // ③ 인스턴스 메서드
    fun display(): String = "$name: $price"

    companion object {
        // ① 클래스 변수 (static과 같음)
        const val DEFAULT_CURRENCY = "KRW"

        // ④ 클래스 메서드 / 스태틱 메서드
        fun fromResult(result: ParseResult): ParseResponse =
            ParseResponse(result.name, result.price)

        fun isValidName(name: String): Boolean =
            name.isNotBlank()
    }
}

// 호출
ParseResponse.DEFAULT_CURRENCY          // 클래스 이름으로
ParseResponse.fromResult(parseResult)    // 팩토리
ParseResponse.isValidName("foo")

정리:

  • Python의 클래스 변수 + @classmethod + @staticmethod = Kotlin의 companion object 내부 선언
  • Python의 인스턴스 변수/메서드 = Kotlin의 클래스 본문 (companion 밖)

Companion object에 주로 넣는 것들:

  1. 상수: const val PARSER_NAME = "og", DEFAULT_CURRENCY, URL 리터럴
  2. 팩토리 메서드: ParseResponse.from(result), User.newFromIdentity(identity)
  3. 공유 상태 없는 유틸: isValidName, parseKrwAmount처럼 어떤 인스턴스에도 묶이지 않는 검증/변환

Companion object에 넣지 말아야 할 것: 인스턴스 상태에 의존하는 로직 (그건 인스턴스 메서드).

왜 Kotlin은 static 키워드를 없앴나 — Java의 static은 클래스에 "붙어있는" 멤버지만 실제로는 별도 공간. OOP 일관성이 떨어짐. Kotlin은 companion이라는 singleton object로 통일해 "클래스 레벨 멤버도 결국 object의 멤버"라는 일관된 모델 제공.

Q. 고급 주제 (코루틴 / delegated property / DSL)는 왜 안 다뤄?

이 프로젝트에 나오지 않기 때문. 그래도 면접에서 언급될 수 있으니 간단히:

주제한 문장 설명이 프로젝트
코루틴 (suspend)비동기/non-blocking 코드를 동기 스타일로 작성. Spring WebFlux, Ktor에서 핵심.안 씀 (Spring MVC 동기 방식)

Q. object의 3가지 형태는?

1. 싱글톤 선언 (object declaration) — 자바의 public static final 상수 모음과 같은 역할.

object ParserNames {
    const val OG = "og"
    const val COUPANG = "coupang-api"
}

ParserNames.OG                  // "og"
ParserNames === ParserNames     // 항상 true

2. companion object — 자바 static의 대체 (이미 위에서 다룸).

3. object expression — 자바 anonymous inner class와 같은 익명 객체. 인터페이스를 그 자리에서 구현한 일회용.

// ParserFactoryTest.kt:28
val dedicated = object : ProductParser {
    override fun canParse(url: String) = url.contains("coupang.com")
    override fun parse(url: String) = ParseResult.Failure("stub", "test")
}

Q. enum은 상수인가 VO인가?

둘 다 맞는 관점.

  • 개별 enum 값 (Mall.COUPANG) — 컴파일 타임 고정 싱글톤이므로 "이름 붙은 상수"로 해석 가능
  • enum 타입 (Mall) — 값으로 정체성 판단하는 "유한 집합의 VO"

Kotlin/Java enum은 C 스타일 정수 상수가 아니라 필드/메서드를 가진 객체:

enum class Mall(val displayName: String) {
    COUPANG("쿠팡"),          // 인스턴스 (displayName="쿠팡")
    ELEVENST("11번가"),
    GENERIC("기타");

    @JsonValue
    fun toJson(): String = name.lowercase()  // 메서드도 가짐
}

→ "싱글톤 VO 인스턴스들의 집합"이라고 부르는 게 가장 정확. 상수·enum·VO는 "불변 값" 공통분모 위에서 "값의 개수와 결정 시점"에 따라 나뉘는 3단계 스펙트럼.

Q. enum의 3가지 문법 형태는?

// ① 생성자 없음, 단순 이름만
enum class AuthProvider {
    GOOGLE;                      // 세미콜론 필수 (아래 메서드 있어서)

    @JsonValue
    fun toJson(): String = name.lowercase()
}

// ② 생성자 파라미터 있음
enum class Mall(val displayName: String) {
    COUPANG("쿠팡"),          // 생성자에 "쿠팡" 전달
    ELEVENST("11번가"),
    GENERIC("기타");
}

// ③ 메서드 없으면 세미콜론 생략 가능
enum class Simple { A, B, C }

Kotlin enum은 항상 name: String과 ordinal: Int를 자동 제공. AuthProvider.GOOGLE.name → "GOOGLE".

Q. class A : B의 콜론(:)은 뭐야?

Kotlin에서 콜론은 인터페이스 구현 + 클래스 상속을 모두 담당. 자바의 implements와 extends를 하나로.

JavaKotlin
class Foo implements Bar { }class Foo : Bar { }
class Child extends Parent { }class Child : Parent() { } (괄호로 상위 생성자 호출)
class X extends Y implements Z { }class X : Y(), Z { }

LinkCart 실제 예:

// application/auth/port/GoogleOAuthClient.kt (포트, 인터페이스)
interface GoogleOAuthClient {
    fun exchangeCodeForIdentity(code: String, redirectUri: String): GoogleIdentity
}

// infrastructure/adapter/auth/GoogleOAuthAdapter.kt (어댑터, 구현)
@Component
class GoogleOAuthAdapter(...) : GoogleOAuthClient {  // ← 인터페이스 구현
    override fun exchangeCodeForIdentity(...) = ...
}

→ Hexagonal Architecture의 port-adapter 패턴이 정확히 이 문법으로 표현됨.

Q. @Value("\${linkcart.google.client-id}")의 \$는 뭐야?

Kotlin 문자열에서 $는 문자열 템플릿 예약 문자. Spring의 Property Placeholder 문법("${...}")을 그대로 쓰려면 이스케이프 필요:

@Value("\${linkcart.google.client-id}")   // Kotlin에서는 \$ 이스케이프
@Value("${"$"}{linkcart.google.client-id}") // 대안 (덜 선호)

// Java에서는 그냥 $로 OK
@Value("${'"'}${'$'}{linkcart.google.client-id}${'"'}")

"${...}" 안의 내용은 Spring이 런타임에 application.yml / 환경변수에서 값을 읽어 주입. 상세는 04. Spring Boot 기초.
